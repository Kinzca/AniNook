# 二次元桌宠与角色分享方案

项目名称：**AniNook**（用户于 2026-10-18 选定）。命名组合为 Anime / Animation + Nook，保留“打破第四面墙，让喜欢的角色贴近生活”的寓意。英文名公开检索暂未发现同名应用或游戏，尚未核实商标、域名及上架名称可用性；此前“次元壁”的[名称检索](../research/name-check-ciyuanbi-2026-10-18.md)保留为历史。

更新：2026-10-18。状态：产品方向与技术验证提案，尚未实现或部署。

最新调研：[Inochi2D 原生 Android 适配与长期维护](../research/inochi2d-android-2026-10-18.md)。用户已优先选择 Android 原生开发，并希望角色动画方案免费开源。Inochi2D 保留为首选验证候选，尚未锁定为生产依赖；此前 [Godot 开源方案比较](../research/open-source-2d-puppets-2026-10-18.md)和下文 Cubism 授权记录保留为历史参考。

## 已明确的需求

- 单人开发，优先 Android 原生开发，面向手机并希望上架 TapTap。Godot 不再作为当前默认主线。
- 角色动画方案希望免费开源，优先核实 Inochi2D；接入不能以未确认的 Live2D 商业授权作为默认前提。
- 免费开放使用；是否保留此前广告目标尚未明确，免费不自动解释为开源。
- 二维立绘式角色，有表情和动作，类似 Live2D。
- 玩家可以导入角色；希望进一步支持上传、分享、下载及玩家自建资源服务器。
- Android APK 是首个技术验证目标。此前便利店与制造方案保留为历史研究，不再作为本轮默认实现。

## 产品假设与事实

产品主张：让玩家把喜欢且获准使用的二维角色带到手机桌面，并方便创作者提供可互动的角色包。

不能以“没有成功产品”作为市场依据：Shimeji 的 Google Play 页面显示累计下载 10M+，并已有动漫角色及导入功能；下载量不是活跃用户或中国市场规模。Shijima 也已有 Android 角色导入。需要验证的差异是立绘表现、表情反馈、创作者制作门槛和国内手机使用体验，而不是单独的“二次元”或“可导入”。

来源：[Shimeji](https://play.google.com/store/apps/details?id=com.digitalcosmos.shimeji)、[Shijima](https://getshijima.app/Shijima)。

## 技术方案与尚未解决的条件

当前建议使用 Android Studio、Kotlin 与 Jetpack Compose 构建应用界面、角色库、设置和下载；由 Android 原生组件处理文件选择、悬浮窗口、权限、通知、服务、锁屏与恢复。具体 SDK/NDK 与最低系统版本待构建验证后固定。

如 Inochi2D 验证通过，角色层采用固定提交的 D 核心、C/C++ JNI 桥与 AniNook 的 OpenGL ES 渲染器；界面预览与悬浮使用同一套渲染实现。先面向 arm64-v8a，其他架构与图形特性按需求扩展。该方案尚未实现，不把 CPU 架构支持或 C 接口存在当作 APK 已可用的证据。

主要未决项包括：Android 工具链与依赖能否稳定构建，桌面 Creator 导出的模型与新 SDK 是否兼容，遮罩/合成/混合绘制是否正确，悬浮 Surface 的销毁恢复与功耗是否可接受。预渲染动画只能作为有限降级模式，不等同于参数化立绘。面向公众前必须定义受支持的模型配置，并对异常导入数据建立校验与失败恢复。

[Android 原生界面](https://developer.android.com/develop/ui/compose/documentation)、[Inochi2D Android 官方讨论](https://github.com/Inochi2D/inochi2d/issues/73)、[源码审查、投入与验收方案](../research/inochi2d-android-2026-10-18.md)。

## 历史比较：Live2D 授权核实结果（当前不作为默认依赖）

Live2D 官方 Expandable Applications 定义包含通过添加文件使用不定数量模型的应用，要求所有发行者在发布前通过专门审核和协议；个人与小型企业的普通豁免不直接适用。官方写明通常要求有效收入模式，完全免费的应用原则上不符合审批条件，但满足另行规定的条件时可能获准。

判断：用户导入模型的桌宠高度符合这一描述，最终归类、是否接受免费模式及费用需要向 Live2D 确认。不能承诺“Godot 免费，所以 Live2D 导入产品也可无条件免费发行”。研发验证与正式发行分别处理；本轮没有发送询问或签约。

若未来重新考虑 Cubism，可使用以下咨询摘要：单人开发 Android 桌宠，用户可导入本地 Cubism 模型，计划提供自建模型源及分享服务，向玩家免费提供。请确认应用分类、免费模式的例外条件、广告如保留时的影响，以及模型分发平台需要满足的授权条件。本轮没有联系对方。

## 角色包提案

面向玩家提供可安装的资源包，不要求玩家安装开发工具。首版只接收声明式数据和媒体文件，不执行包内脚本、原生库或任意插件代码。

建议包内容：版本化 manifest.json、模型及贴图、动作/表情、预览图、作者与授权信息、互动映射。Inochi2D 候选使用其模型数据；最终支持的 INP/INX 内容版本、节点和渲染能力由兼容样本确定，不承诺任意同后缀文件可用，也不承诺读取 Live2D moc3 或任意 3D 模型。外层包版本与模型格式版本分开管理。

互动映射把“待机、点击头部、拖拽、早晚问候”等有限事件映射为表情、动作和台词。缺失动作有默认行为。资源导入须验证路径、解压后大小、贴图尺寸、引用完整性与模型兼容版本；超限给出可理解的修复提示，阈值由真机测试设定。

购买模型、可个人使用与允许公开再分发是不同授权。上传流程记录作者、来源、展示/下载授权；平台保留举报和下架能力。客户端能下载的模型不能承诺无法被提取。

## 分享和自建服务器

建议第一版资源源协议只包括 HTTPS 索引、封面、角色包版本、兼容版本、文件大小、校验值和下载地址。用户手动添加信任的源，明确显示来源，逐个选择下载；自建源不会自动进入官方推荐列表。校验值验证完整性，不证明来源可信或版权合法。

先使用可静态托管的只读角色目录，便于玩家自己搭服务器；统一格式保留未来增加搜索和分页的空间。之后再提供可自建的上传服务：账号、上传隔离区、检查/审核、发布目录、对象存储和下载。用户上传不直接公开。

官方社区承担作品审核、授权记录、删除/投诉处理及存储流量成本。免费面向玩家不代表运营成本为零。当前不部署服务器，不要求玩家登录官方账号才能使用本地角色包。

## 验证顺序

1. 先验证 Android arm64 可重复构建及 JNI 模型加载，再用至少 3 个有适当许可的模型验证形变、遮罩、合成和物理；然后验证真机悬浮、触摸、前后台和锁屏。建议先设 5–10 个实际开发日的评估预算，并按证据决定是否追加，不将其视为完成移植的承诺。
2. 本地角色包：找两名创作者，使用不同模型完成制作、导入、交互映射与切换，记录额外适配工作。
3. 私人资源源：添加源、浏览、下载、校验和导入；关闭服务器后已下载角色仍可使用。
4. 小范围分享：上传、审核、下载及撤回跑通后，再扩大为公共社区。

首轮看玩家是否愿意留下角色、会不会因遮挡或耗电关闭它、创作者能否自行制作可用角色包。原便利店的工期、预算与广告指标不能直接移植到本项目；待 Android 构建、角色兼容和悬浮实测明确后重新估算。当前未安装工具链、创建 Android 工程或进行真机测试。
